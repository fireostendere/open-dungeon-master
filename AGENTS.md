# Инструкция для AI-агентов — Open Dungeon Master

Рабочий корень — каталог этого файла и `package.json`, а не дополнительный
подкаталог `open-dungeon-master/`. Версии Node, Next, React и зависимостей берите
из манифеста и lockfile, а не из старых инструкций или названия ветки.

## Разработка и границы доступа

Изменение кода, слияние веток и развёртывание — разные действия. Запрос на merge
не разрешает SSH, `odmctl update`, восстановление или запись в производственную
базу. Не отключайте защиту ветки, проверки, авторизацию, CAS прогресса или
проверку MCP preload ради успешного теста. Не выдавайте запуск с тестовыми
зависимостями за полный браузерный/SDK/production прогон.

Архитектура: Next/React-интерфейс, серверные доменные операции в `src/lib`,
SQLite-драйвер с поддержкой SQLCipher и отдельный непривилегированный MCP-сайдкар.
MCP вызывает `/api/internal/mcp`; он не получает Docker socket или файл игровой БД.
Секреты не должны попадать в код, параметры команд, логи, историю агента или чат.

Справочные пути управляемой установки: `/opt/odm`, репозиторий
`/opt/odm/repository`, состояние `/opt/odm/state`, токен
`/opt/odm/config/mcp.token`, реквизиты администратора
`/opt/odm/config/admin.json`. Упомянутый в прежней документации хост
`api.iroslyakov.com` и его доступность этим merge не проверялись. Сначала прочитайте
актуальную конфигурацию конкретной установки при наличии разрешения оператора.

Команды оператора: `odmctl status`, `odmctl logs -f`, `odm-mcpctl status`.
`odm-mcpctl token` выводит путь, а `token --show` — секрет. Не публикуйте его вывод.
Операции обновления/backup/restore/MCP sync используют общий installation lock;
не возвращайте старый независимый таймер или обход блокировки переменной окружения.

## Внешний ведущий

Прочитайте `.opencode/skills/odm-narrator/SKILL.md`, `docs/external-narrator.md`
и MCP-ресурсы `odm://narrator/instructions`, `odm://narrator/playbook`.
`odm_narrator` содержит connect, read, catalog, invoke, narrate, release_floor,
answer_ask. Их внутренние имена имеют префикс `narrator.`.

Модель описывает мир и отыгрывает NPC; игроки решают за своих персонажей. Движок
владеет костями, HP, инвентарём, ячейками, инициативой и результатами механик.
Не придумывайте бросок текстом и не применяйте повторно урон или награду,
которые уже применил сервер. Перед действием изучите актуальный catalog.

Внешний narrator требует human-DM mode с местом ведущего, без активной передачи
управления серверному AI, без TTS и автоматических карт. Записи сюжета требуют
активной кампании. Настройки меняются только в рамках запрошенной операции.

Читайте события через read, передавая `nextCursor` до `hasMore:false`. Пустая
страница после фильтрации OOC не означает конец потока. Для одного invoke,
narrate или release_floor используйте `expectedSeq` последнего полностью
прочитанного состояния. После каждой записи, 409, тайм-аута или обрыва перечитайте
и проверьте результат. Никогда не повторяйте неоднозначную запись автоматически.
`release_floor` снимает hold, сохраняя вложенный floor; он не отменяет инициативу.

## Реплики и Ask

Речь имеет голубое оформление и кавычки; действие — янтарную полосу; OOC —
приглушённую пунктирную рамку. Подписи поддерживают RU/EN/PL. Это отображение,
а не переписывание сохранённого текста. OOC исключён из narrator-сообщений и
событий, но остаётся в чате участников. Direct/Lead остаётся отдельным системным
указанием. Личный язык интерфейса не меняет общий язык повествования кампании.

Проверяйте `asks` при каждом read, даже если sequence сюжета не изменился.
`answer_ask` требует `campaignId`, `askId`, непустой `answer` до 4000 символов;
допустимы `citations` и необязательный `expectedSeq`. Ответ ограничен кампанией
вопроса и не продвигает сцену или ход. В режиме human исходная запись содержит
локализованное подтверждение передачи вопроса, которое ведущий заменяет ответом.

Приватные вопросы видят автор и доверенный оператор/narrator, не весь стол.
В событиях нет текста вопроса/ответа. Приватное уведомление адресуется нужному
пользователю; общего persisted `ask_submitted` с содержимым больше нет.
Не переносите приватный Ask, шёпот, outline или DM-секрет в общую реплику.
Bearer даёт права оператора, а не отдельного игрока: не подключайте его в
недоверенный клиент игрока.

Длительная реактивная сессия требует реально работающего клиентского цикла
чтения/подписки. Ресурс или skill не запускает фонового агента сам. Скрипт
`/opt/odm/tools/watch-player.sh` не является гарантированной частью репозитория;
не обещайте его наличие или пробуждение модели без проверки реализации.

## Проверки

Из корня зависимостями оснащённого checkout:

```sh
npx --no-install tsc --noEmit
npm test
npm run build
node scripts/test-mcp-tools-contract.mjs
node scripts/test-mcp-narrator-control.mjs
node --experimental-vm-modules --test scripts/test-merge-*.mjs
```

Последний набор — отдельные модульные/интеграционные проверки с явно указанными
заменами зависимостей. Полная приёмка не следует из их успеха. Решения по
объединению веток и фактически выполненные проверки описаны в
`docs/merge-2026-09-17.md`; предыдущая приёмка ревью — в
`docs/review-2026-09-16-status.md`.

Индекс навыков: `docs/agent-skills.md`. Навыки подготовки мира, персонажей,
встреч, правил, лута и эксплуатации сохраняются в `.opencode/skills/`.
