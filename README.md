# Dungeon Master — общий AI D&D-сервер

Приватный форк Open Dungeon Master: несколько игроков в браузере, текстовый AI-DM,
карты и статичные токены, персонажи, история и постоянная шифрованная SQLite-база.

## Установить одним файлом

Скачайте из **этого репозитория** один файл и перенесите на целевую машину.
Установщик сам получает остальной код и собирает **этот форк**, а не чужой образ.
Приватный GitHub-репозиторий требует вашего доступа: read-only token с разрешением
Contents для одного репозитория. Токен вводится скрыто либо передаётся файлом.
Вход в аккаунт LLM выполняется отдельно владельцем аккаунта в админке.

| Где | Файл | Запуск |
|---|---|---|
| Ubuntu 22.04/24.04/26.04, Debian 12/13 | [`install-server.sh`](install-server.sh) | `sudo bash install-server.sh` |
| Windows 10/11, Docker Desktop / WSL2 | [`install-local.ps1`](install-local.ps1) | `powershell -NoProfile -ExecutionPolicy Bypass -File .\install-local.ps1` |
| Linux-компьютер с локальной моделью | тот же `install-server.sh` | `sudo bash install-server.sh --mode local` |

На Windows разрешение выполнения меняется только для одного процесса, не глобально.
WinGet устанавливает недостающие зависимости; Docker Desktop может запросить UAC,
первичное согласие или включение виртуализации. Если нужен reboot, установщик
сохраняет параметры и регистрирует продолжение при следующем входе; сам ПК не перезагружает.

Предварительный просмотр без изменений: `bash install-server.sh --plan` или
`.\install-local.ps1 -Plan`.

## Что делает управляемая установка

Один процесс приложения и одна постоянная SQLite-база; несколько реплик запрещены.
Изолированный runtime с официальным Codex CLI для ChatGPT; Ollama по выбору либо
существующий совместимый backend. Веб-админка на русском для подключения моделей.
Первый администратор создаётся **до публикации веб-порта**, со случайным паролем,
который нужно поменять при первом входе. Открытая регистрация не включается.

Данные, картинки, ключи БД и состояние авторизации отделены от кода и обновлений.
Docker перезапускает упавшее приложение; watchdog следит за web/DB readiness,
местом на диске и свежестью бэкапов. Есть ограничение числа рестартов, журнал
незавершённого обновления, откат приложения **вместе с БД**, шифрованные restic-бэкапы,
проверка восстановления и необязательная удалённая копия.

## Первый вход

По умолчанию откройте `http://localhost:3005`. Файл первоначальных реквизитов:
Linux — `/opt/odm/config/admin.json`; Windows — `%LOCALAPPDATA%\OpenDungeonMaster\config\admin.json`.
Сначала смените пароль, затем откройте **Admin → Подключения LLM** и настройте DM.
Для друзей создайте кампанию и выдайте приглашения.

Для публичного сервера задайте домен при установке: Caddy настроит HTTPS.
Домен должен указывать на сервер, а TCP 80/443 быть доступны. Без домена приложение
слушает только localhost; внешняя публикация и открытие firewall молча не выполняются.

## Основные команды

На Linux используйте `sudo odmctl …`; на Windows — `…\OpenDungeonMaster\odmctl.cmd …`.

```bash
sudo odmctl status
sudo odmctl auth login chatgpt --device
sudo odmctl auth models chatgpt
sudo odmctl auth connect chatgpt --model EXACT_MODEL_ID --apply
sudo odmctl backup
sudo odmctl snapshots
sudo odmctl restore-check latest
sudo odmctl update
sudo odmctl rollback --yes
sudo odmctl recovery-kit
```

Автообновление по умолчанию **не включено**: таймер проверяет новые коммиты.
`--auto-update` / `-AutoUpdate` включает обновление в окне обслуживания.

## Важные границы

Установка сервера не заменяет доступ к приватному репозиторию, авторизацию LLM,
DNS или настройки гипервизора. На Windows ПК должен быть включён, не спать,
а Docker Desktop и пользовательская сессия — работать. Linux-server вариант
предназначен для автономного запуска после перезагрузки.

Непрерывная работа — это автозапуск и восстановление после сбоев, не обещание 100%
доступности. Для согласованного бэкапа и применения обновления приложение кратко
останавливается. Бэкап на том же диске не спасает от гибели диска: настройте off-site
и сохраните **пароль restic отдельно от сервера**.

Графика использует существующие ComfyUI или облачные image-провайдеры. Установщик
не объявляет placeholder сгенерированным изображением, не скачивает без выбора
десятки гигабайт image-моделей и не обещает поддержку любой GPU.
