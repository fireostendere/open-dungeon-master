# Разработка ODM

Прочитайте [общий контракт](../../../docs/agent-skills.md#общий-контракт-и-границы) и
[границы проверок](../../../docs/deployment-testing.md). Навык работает с исходниками,
не с live-кампанией.

## Вход

- Симптом, ожидаемое поведение и, если есть, воспроизведение.
- Затронутый экран, API или доменный объект; спросите только недостающее для риска.

## Порядок работы

1. Прочитайте `AGENTS.md`; перед правкой Next-кода прочитайте относящийся guide в
   `node_modules/next/dist/docs/`.
2. Найдите символ, его callers и тесты (`rg`); пройдите API → service → DB/UI.
3. Сначала добавьте самую узкую регрессионную проверку или воспроизведите дефект.
4. Переиспользуйте существующую абстракцию и исправьте общую первопричину, не UI-симптом.
5. Не меняйте schema, provider, MCP или runtime prompt без явного задания.
6. Запустите релевантный test; при необходимости `npm run lint`, а при TS-изменении
   `node_modules/.bin/tsc --noEmit` (отдельного npm typecheck нет).
7. `npm run test:providers`, build и deploy-проверки — только когда затрагивают их
   границу; не запускайте live/external проверки по умолчанию.

## Результат

```text
Причина: …
Изменение: файлы и поведение
Проверка: команда → результат
Риск/не запускалось: …
```

Готово, когда проверка ловит старую ошибку, все места вызова проверены и целевая проверка проходит.
