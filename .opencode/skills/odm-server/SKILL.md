# Сервер ODM

Сначала прочитайте [общий контракт](../../../docs/agent-skills.md#общий-контракт-и-границы),
[установку](../../../docs/installation.md) и [operations](../../../docs/operations.md).

## Минимальные сведения

ОС, точный путь установки и её корень, тип установки (управляемая или ручная), доступ
(локально/SSH), симптом и согласованное окно простоя. Сначала подтвердите эти данные.
Не запускайте установщик ради диагностики: `install-server.sh --plan` — лишь предварительный просмотр.

## Действия

1. Для управляемой Linux-установки используйте `sudo odmctl status`, для Windows — её
   установленный `odmctl.cmd`. Для ручной установки следуйте её документации, не угадывайте `odmctl`.
2. При диагностике прочитайте журналы, готовность и место на диске; `/api/health` — проверка
   живости, `/api/ready` — web и шифрованной БД. Не перезапускайте здоровую БД из-за сбоя провайдера.
3. `start` и `stop` меняют доступность и требуют согласованной операции. Для остановки успех —
   намеренно остановленное приложение, а не `/api/ready`.
4. До обновления запишите текущую версию, ref и источник сборки, целевой ref, снимок и стратегию
   отката, а также явно согласованное окно простоя вне сессии. Диагностика не добавляет `--yes` и не мигрирует.
5. Сначала `check-update`; `update --ref COMMIT` собирает управляемый образ этого коммита форка.
   Не заменяйте его compose из checkout или upstream `latest`.
6. Откат — отдельное явное одобрение с описанием версии, снимка, простоя и потери новых ходов;
   используйте [odm-backup](../odm-backup/SKILL.md).
7. Не убивайте чужой процесс, не публикуйте Docker/Ollama/MCP и не меняйте firewall, DNS, GPU
   или системные задачи без отдельного поручения. Один процесс ODM — один writer.
8. Для Node-разработки, build или проверки исходников перейдите к [odm-development](../odm-development/SKILL.md),
   а не к установщику.

## Отчёт

```text
Установка/путь/тип: … | Наблюдение: статус, `/ready`, журналы без секретов
Текущая/целевая версия и ref: … | Снимок/откат/простой: …
Следующее действие: только чтение / согласованное изменение
```

Готово, когда причина локализована; запуск/обновление подтверждены `/api/ready`, а остановка —
намеренно остановленным состоянием.
