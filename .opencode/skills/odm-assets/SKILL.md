# Арты ODM

Прочитайте [общий контракт](../../../docs/agent-skills.md#общий-контракт-и-границы)
один раз за задачу. Для готового файла сразу используйте следующий раздел;
для генерации/Asset MCP прочитайте нужный раздел
[изображений](../../../docs/image-generation.md) и
[внешних изображений через MCP](../../../docs/external-assets-mcp.md).

## Готовая картинка

1. Используйте переданный файл/вложение; подтвердите, что доступны именно его байты,
   проверьте MIME и размер (PNG/JPEG/WebP ≤ 8 МиБ). Не генерируйте замену вложению.
   Отсутствующий файл уточните, не ищите случайный похожий файл по всему диску.
2. Возьмите ID цели из ответа её создания или текущего чтения. `campaign` — обложка,
   `library_character` — портрет шаблона с зеркалированием в копии;
   `sheet` — только один живой лист. Сохраняйте действительные права оператора.
3. Предпочтите `odm_assets.set_image` через настроенный MCP. Для большой локальной
   картинки, которую нельзя передать без помещения base64 в контекст, используйте
   [scripts/set-image.py](scripts/set-image.py) — Python stdlib, без установки SDK.
   Он читает байты и операторский token-файл локально, вызывает только публичный
   `/mcp`, проверяет capabilities и `expected_url`, делает одну запись и выводит
   только сохранённые метаданные. Не передавайте ему narrator-токен и не подменяйте
   credential после отказа в правах.

   ```sh
   python3 .opencode/skills/odm-assets/scripts/set-image.py \
     --url https://your-odm-host.example/mcp \
     --token-file "$HOME/.config/odm/mcp.token" \
     --type campaign --id "$CAMPAIGN_ID" --file /path/to/cover.png
   ```

   Пути команды — от корня репозитория. Endpoint возьмите из действительной
   конфигурации оператора. По умолчанию ожидается пустое поле (`expected_url: null`);
   для согласованной замены передайте `--expected-url /uploads/<old-file>` из чтения.
   Redirect не выполняется; токен/base64 не выводятся. При неизвестном результате
   скрипт не повторяет запись: сначала прочитайте `get_image` и сравните цель/hash.
4. Проверьте `target`, `image.url`, `sha256`, `byteSize` сохранённого ответа.
   Успешный полный ответ не требует дополнительного `get_image`; перечитайте
   только неполный/неоднозначный результат. `include_data: true` нужен для скачивания,
   не для проверки привязки. Не создавайте pack/job/lease для уже готовой картинки.

Проверка загрузчика без сервера и токена:
`python3 .opencode/skills/odm-assets/scripts/test-set-image.py`.

## Вход

Нужны тип материала, целевая кампания/карта/персонаж, стиль, права, сервис и разрешение на расход.
Материал, ожидающий создания, остаётся черновиком или задачей, а не изменением действующей
карты, коллизий или LOS.

## Порядок

1. Различайте статичный фон, портрет, токен и игровую геометрию: изображение карты не создаёт
   стены, коллизии, LOS или секретные слои.
2. До команды проверьте настроенный сервис и его процесс; не устанавливайте узлы, не скачивайте
   модели и не открывайте ComfyUI в интернет.
3. Если выбран навык хоста `bailian-gen`, используйте его, не меняя глобальное значение по умолчанию.
4. Для Asset MCP сначала проверьте схему и статус; следуйте фактической цепочке
   packs → jobs → leases → одноразовая загрузка/скачивание → привязка к цели.
   Для готового файла используйте короткий операторский путь `odm_assets.set_image`:
   `target: {type: "library_character" | "sheet" | "npc" | "campaign", id}`, байты
   в `data_base64`, `mime_type`, необязательный `name`. Первые три цели — портрет,
   `campaign` — обложка. Кампания/pack/job для библиотечного портрета не нужны.
   `get_image` возвращает метаданные, `include_data: true` — также base64;
   `delete_image` требует `confirm: true`. Для замены/удаления передайте
   `expected_url` из чтения; `null` означает ожидание пустого поля. Файл с другими
   ссылками, включая события/снимки, сохраняется. PNG/JPEG/WebP, максимум 8 МБ.
   Локальный путь не является загрузкой: байты читает авторизованный клиент,
   sidecar не читает диск хоста и не скачивает произвольные URL. Restricted narrator
   не получает эти операторские права; используйте согласованный операторский канал.
5. Проверяйте sha256, цель и вариант. Не выводите двоичный API из исходников.
6. Принимайте PNG/JPEG/WebP. После настоящего создания проверьте отдельно фон и движение
   токена через [обработчики карт](../../../src/app/api/campaigns/%5BcampaignId%5D/dm/maps/route.ts)
   и [геометрию](../../../src/lib/battlemap/).
7. Сохраняемые файлы входят в бэкап ODM, но внешние веса и кэш — нет.

## Результат

```text
Материал/цель/права: … | сервис/задача: …
Статус: черновик / создан / привязан
Проверка файла и привязки: … | геометрия/LOS: отдельно не заявлены
```

Готово, когда конкретный файл и его безопасная привязка к цели проверены.
