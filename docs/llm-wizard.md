# Мастер подключения модели (LLM wizard)

Единая точка подключения текстовых моделей для AI-DM: облачные провайдеры,
локальные runtime и произвольные OpenAI-совместимые endpoint. Открывается в
**Admin → Settings → Text model defaults → «Мастер подключения модели»**.
Та же кнопка предлагается при первом запуске, когда модель ещё не подключена.

## Шаги мастера

1. **Тип подключения** — облачный провайдер (OpenRouter, OpenAI, DeepSeek,
   Alibaba Cloud/DashScope), локальный runtime (Ollama, llama.cpp, LM Studio,
   vLLM) или произвольный совместимый endpoint. Пресет подставляет base URL,
   протокол и способ авторизации; всё можно изменить вручную.
2. **Адрес и доступ** — base URL, API key (для доверенного локального сервиса
   ключ не требуется), отдельные поля: предел контекста, max output tokens,
   thinking (on/off/auto), таймаут запроса.
3. **Модель** — «Загрузить список» (GET /v1/models или Ollama /api/tags) либо
   ручной ввод model ID. Отсутствие endpoint списка моделей не блокирует
   backend: ручной ввод всегда доступен.
4. **Проверка** — настоящая проверка, а не «Привет»: см. ниже.
5. **Сохранение** — именованный профиль; «Применить как DM (глобально)»
   доступно только после прохождения проверки инструментов.

## Что реально проверяет probe

| Этап | Что доказывает |
|---|---|
| `models` | Доступность списка моделей; 401/403 → «Неверный ключ или нет доступа». Информационный: ручной model ID допустим. |
| `chat` | Аутентификация, доступ к модели, русский ответ на короткий запрос. |
| `stream` | Streaming (SSE-чанки). Информационный: влияет на флаг возможности, не на общий вердикт. |
| `tool_call` | **Настоящий function call**: модель должна вернуть `tool_calls` с валидным JSON `{word:"куб", n:7}`. Модель, которая лишь пишет имя инструмента в тексте, проверку НЕ проходит. |
| `tool_result` | Возврат результата инструмента и продолжение ответа моделью (без повторного вызова). |

Общий вердикт `ok` = chat + tool_call + tool_result. Возможности профиля
(`tools`, `streaming`, `modelListed`) и дата последней проверки сохраняются.
Backend без надёжных tools можно сохранить с предупреждением, но нельзя
включить как автоматического DM.

**Важно**: успешный probe доказывает техническую совместимость, не качество
DM. После подключения сделайте игровой smoke-ход в реальной кампании.

## Профили и хранение

- Профили живут в серверной БД (app_settings, ключ `llm_profiles`), БД
  шифруется at rest штатным механизмом (`DB_ENCRYPTION_KEY`).
- API key никогда не возвращается клиенту: в ответах только `hasApiKey`.
  Пустое поле ключа при редактировании = «сохранить прежний», явная пустая
  строка через API = «очистить».
- «Применить» записывает существующие поля конфигурации (global config или
  story settings кампании) — никакого параллельного конвейера настроек;
  DM-ходы используют штатный механизм резолюции.
- Сохранение атомарно (одна запись JSON-массива), последний рабочий профиль
  не уничтожается.

## SSRF-политика

Все пользовательские URL перед серверным запросом проходят `assertSafeEndpointUrl`:
только http/https; блокируются link-local (169.254.0.0/16), metadata-endpoint'ы
(169.254.169.254, fd00:ec2::254, metadata.google.internal), CGNAT (100.64.0.0/10)
и не-http схемы. Локальные и LAN-адреса разрешены (в них смысл). Запросы не
следуют редиректам (redirect: manual), Authorization не переносится на чужой
host. Маршруты доступны только администратору (`requireAdmin`).

Ограничение: guard проверяет литералы хостов; DNS-имя, разрешающееся в
заблокированный IP, не отсеивается (DNS rebinding). Для admin-only формы на
доверенном сервере это приемлемо; при публикации сервера в интернет учтите.

## Шаг графики (ComfyUI)

**Admin → Settings → Image generation → «Проверка графики (ComfyUI)»**:

- «Проверить доступность» — статус ComfyUI из backend + список реально
  установленных checkpoint'ов (без выдуманных имён).
- Выбор checkpoint из списка; «Использовать по умолчанию» подставляет его в
  поле ComfyUI checkpoint (сохраните настройки панели).
- «Тест генерации» — настоящая генерация через штатный workflow ODM;
  показывается фактический PNG и время. На общей с LLM GPU это может занять
  минуты — очередь графики не блокирует текстовый чат.
- Отсутствующий checkpoint → понятное сообщение со списком установленных.

## API-маршруты (admin-only)

- `GET/POST/DELETE /api/admin/llm-profiles` — CRUD профилей (masked).
- `GET/DELETE /api/admin/llm-profiles/[id]` — один профиль.
- `POST /api/admin/llm-profiles/[id]/probe` — проверка сохранённого профиля
  (persist lastCheck).
- `POST /api/admin/llm-profiles/[id]/apply` — `{scope:"global"}` или
  `{scope:"campaign", campaignId}`.
- `POST /api/admin/llm-probe` — ad-hoc проверка до сохранения.
- `POST /api/admin/llm-models` — список моделей endpoint'а.
- `POST /api/admin/image-probe` — статус ComfyUI + тестовая генерация.

## Тесты

- `scripts/test-llm-profiles.mjs` — детерминированные mock-тесты: CRUD и
  маскирование ключей, SSRF-guard, probe против локального mock-сервера
  (happy path, текст-вместо-tool-call, невалидные аргументы, 401, 429,
  таймаут, ручной model ID без /models).
- Реальные интеграционные проверки (локальный Qwen через Ollama, ComfyUI на
  GPU) — см. `docs/acceptance.md`. Mock не доказывает работу реальной модели.
