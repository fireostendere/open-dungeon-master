# Явная боевая заявка и быстрый путь хода

## Поведение

- Выпадающие списки служат для просмотра; только «Добавить» включает действие
  в видимый план. Просмотренная способность не попадает в отправляемый payload.
- Поддержаны три формы: свободный текст, выбранные действия без описания,
  выбранные действия с описанием. В сообщении мастеру выделены явный план и текст.
  План задаёт приоритет применения; противоречие/отмену ведущий уточняет.
- Свободная YOLO-формулировка остаётся полноценной заявкой. План без прозы получает
  краткий нейтральный итог, даже в YOLO. Наличие способности в листе не является
  согласием на её применение.
- Sneak Attack требует `pc_attack(sneakAttack:true)` из заявленного намерения;
  проверки оружия, преимущества и ограничения на ход остаются в движке.

## Ускорение

MCP снова прикладывает bounded live `readAfter` к story writes по умолчанию
(128 КиБ, с пагинацией). Явные параметры, revision/cursor и `false` сохраняются.
Полностью прочитанный attached state заменяет отдельный snapshot/read. Ошибка
readback не отменяет успешную запись и не разрешает повтор эффекта.

Для монаха 2014 `use_resource(ki,variant:hand_of_healing,targetCharacterId)`
проверяет способность, платит действие/ки, бросает лечение и меняет HP.
`flurry_of_healing` после Attack платит бонусное действие и одно ки, заменяет
один удар лечением. Оставшийся заявленный удар —
`pc_attack(weapon:"Unarmed strike",flurry:true)`. `flurry_of_blows` даёт два
отдельно учитываемых безоружных удара. Все части помещаются в один `combat_turn`;
при pending roll/отказе подтверждённые шаги сохраняются, повторять их нельзя.

Штатный путь составного хода: read входа → combat_turn + attached state →
narrate + attached state, при уже известных схемах и без pending/конфликта.
Это уменьшение числа последовательных решений модели; **не измерение времени
ответа живой модели** и не обещание секунд вместо минут. Приватный Ask, поиск
нового правила, конфликт или физические кости могут требовать дополнительных шагов.

Границы: ведущий проверяет касание для лечения по сцене; автоматической проверки
дистанции лечения здесь нет. Поддержана одна замена удара на лечение; дополнительные
эффекты Mercy уровней 6/11 не добавлены. Контракт connect повышен до v7:
`explicitSneakAttack`, `mercyHealing2014`; ведущему нужно обновить кеш схем.

## Проверки

- Регрессии сначала падали: автоматический Sneak Attack, отсутствующий readAfter,
  неразличимый формат свободной и явной заявки.
- `test-combat-dialogue-integration.mjs`: реальная изолированная SQLite, составной
  ход Mercy, ки/HP/инициатива, запрет лишних действий, сохранение receipt при replay,
  opt-in Sneak Attack с физическими костями.
- `test-combat-turn-intent.mjs`, `test-combat-turn-lifecycle.mjs`: три формы заявки,
  серверный приём и неизменность ресурсов до разрешения мастером.
- Транспорт, narrator lifecycle/readback, бюджет действий, каталоги и классовые
  ресурсы проверены существующими целевыми наборами.
- `TMPDIR=/tmp/opencode node scripts/e2e/combat-hud-fixture.mjs`: изолированный
  production-сервер, три формы браузерной отправки, просмотр без выбора, общая
  очередь питомца/героя, сохранение черновика при OOC, блокировка, десктоп/мобильный.
- `tsc --noEmit`, `npm run build`, `npm run i18n:check` прошли. ESLint затронутого
  TS-кода: 0 ошибок, прежнее предупреждение `_ignored` в narrator control.
