# Игровые роли и локальный narrator-host

По умолчанию `narrator/run.mjs` остаётся сборщиком контекста: без явно выбранного
адаптера он не генерирует историю. Новый адаптер добавляет одного ведущего-арбитра,
необязательного литературного автора и отдельные ответы на Ask. Движком правил
остаётся ODM, а не модель. Все записи выполняет host, последовательно.

## Что реализовано

- Арбитр видит сцену, листы, встречу, факты, NPC и подтверждённые результаты.
  Он выбирает действия из актуального серверного каталога; подробные поля можно
  запросить отдельно через решение `catalog`, не загружая весь каталог каждый ход.
- Автор вызывается только по решению арбитра для содержательной сцены. Получает
  публичный контекст и одобренный черновик, но не сырые листы, Ask, whispers,
  секретный план или характеристики врагов. Автор не имеет инструментов записи.
- Ask обрабатывается отдельным запросом с контекстом конкретного автора. Ответ
  возвращается через `answer_ask`, не публикуется в истории и не двигает ход.
- Профиль актёра создаёт только намерение персонажа. Автоматические сообщения
  отсутствующих игроков по-прежнему отправляет существующий серверный autopilot,
  только после его ручного включения. Host не выдаёт токены и не имперсонирует игроков.
- Серверный доппельгангер получает личность, предысторию и текущие ограничения
  персонажа отдельно от доверенной инструкции. Повторные вызовы завершения одного
  раунда объединяются; возвращение игрока или отключение autopilot отменяет ещё
  не опубликованный ответ бота. Это не новый полноценный тактический автопилот.
  Он продолжает использовать настроенную utility/story-модель кампании;
  подключение OpenCode не переключает её автоматически.

## Подготовка

Нужны работающий OpenCode V2 с уже настроенным выбранным провайдером, доступный
Control API ODM, campaign-scoped narrator-token и ID разрешённой кампании.
Провайдерские ключи адаптер не извлекает: ими продолжает управлять OpenCode.
В кампании должны выполняться требования `narrator.connect` из
[протокола внешнего ведущего](external-narrator.md).

Создайте отдельный пустой рабочий каталог на машине OpenCode, вне репозитория
разработки и каталогов с его `AGENTS.md`. Из корня этого репозитория:

```sh
node narrator/export-opencode-workspace.mjs /srv/odm-narrator-workspace
```

Экспорт создаёт `opencode.json` с профилями `narrator-referee`, `narrator-writer`
и `narrator-actor`, канонической игровой политикой и V2 `permissions` deny-all.
Непустой каталог не перезаписывается; глобальные настройки не меняются.
Каноническая политика также устанавливается в API-managed инструкции сессии
перед игровыми данными. Политика не заменяет серверную авторизацию.

Адрес рабочего каталога относится к машине OpenCode. Удалённому OpenCode нужен
HTTPS; незашифрованный HTTP разрешён только для loopback. Перенаправления запрещены.
Не используйте для игры общую кодовую сессию администратора.

## Запуск

Перед запуском оператор предоставляет через защищённое окружение
`ODM_CAMPAIGN_ID`, `ODM_MCP_NARRATOR_TOKEN` и при необходимости
`ODM_OPENCODE_TOKEN` для авторизации в OpenCode. Не помещайте значения токенов
в чат, отслеживаемые файлы или ролевые инструкции.

```sh
export ODM_NARRATOR_ADAPTER_MODULE='file:///opt/odm/repository/narrator/local-role-adapter.mjs'
export ODM_MCP_URL='http://127.0.0.1:3005/api/internal/mcp'
export ODM_OPENCODE_URL='http://127.0.0.1:4096'
export ODM_OPENCODE_WORKSPACE='/srv/odm-narrator-workspace'
export ODM_OPENCODE_PROVIDER='operator-selected-provider'
export ODM_OPENCODE_MODEL='operator-selected-model'
# Optional: ODM_OPENCODE_VARIANT, preserving the explicitly selected variant.
export ODM_NARRATOR_START_AFTER_SEQ=0
node narrator/run.mjs --campaign "$ODM_CAMPAIGN_ID"
```

Путь адаптера должен указывать на установленный локальный модуль. Значения
provider/model обязательны: скрытого перехода на глобальную модель нет.
Созданная OpenCode-сессия проверяется на совпадение выбранных роли и модели.
После генерации удаляется только собственная временная сессия адаптера.

### FULL и YOLO

Этот встроенный `local-role-adapter.mjs` маркирует источник как доверенный
`custom-opencode`, поэтому в обычном запуске он получает **FULL** orchestration:
до 24 referee-шагов и отдельный writer там, где арбитр его запросил. Все другие
источники narrator по умолчанию получают **YOLO**.

Чтобы явно включить YOLO даже для custom OpenCode:

```sh
node narrator/run.mjs --campaign "$ODM_CAMPAIGN_ID" --yolo
# или
ODM_DND_MODE=yolo node narrator/run.mjs --campaign "$ODM_CAMPAIGN_ID"
```

В YOLO host сокращает публичную историю, фильтрует каталог до основных
боевых/состояний, не тратит отдельный вызов writer и по умолчанию ограничен
шестью referee-шагами. Игровой текст не может переключать режим.

`ODM_NARRATOR_START_AFTER_SEQ=0` подходит новой кампании. Для существующей это
должна быть **явно выбранная граница уже обработанных игровых сообщений**, а не
`currentSeq` после административных записей. При первом включении автоматики
старый checkpoint сборщика не считается доказательством обработки игрока.
В дальнейшем очередь и обработанная граница восстанавливаются из checkpoint.

Приведённая команда запускает host непосредственно через Node. Docker-режим
существующего `deploy/narratorctl.py` пока не настраивает этот адаптер и его
OpenCode-окружение автоматически. Боевой запуск и supervisor настраиваются
оператором отдельно; эта реализация сама ничего не развёртывает.

## Последовательность и восстановление

Host сохраняет сообщения каждой полностью прочитанной страницы до продвижения
cursor. Точный payload, UUID `commandId` и `timelineEpoch` записываются до команды.
После записи состояние перечитывается. Неоднозначный результат допускает только
один повтор того же запроса, в том числе после перезапуска.
Для приватных ответов Ask число попыток также сохраняется: третья отправка
блокируется, проблема видна оператору в статусе, а не публичному чату.
`/healthz` при такой остановке возвращает HTTP 503. Оператор или supervisor должен
отслеживать этот сигнал: автоматического обхода лимита повторов нет.

Одна заявка может потребовать нескольких действий движка. Успешный `invoke` не
считается завершением заявки. Физические кости требуют соответствующего
`roll_result` по ID; исчезновение pending roll само по себе не разрешает исход.
Если pending roll завершился раньше, чем host смог установить его ID, автоматика
останавливается для сверки, а не выдумывает результат. Повествование не завершает
инициативу автоматически; `end_turn` остаётся отдельным решением.

Если во время генерации изменилось состояние, черновик не записывается на новом
cursor без переоценки. После rewind старые команды и контекст сбрасываются,
автоматическая обработка останавливается. Оператор выбирает новую обработанную
границу и запускает:

```sh
node narrator/run.mjs --campaign "$ODM_CAMPAIGN_ID" --resume --after "$HANDLED_PLAYER_SEQ"
```

После обычной ошибки модели `--resume` сохраняет текущую заявку и уже выполненные
механики. Он **не разрешает третий повтор** неоднозначной команды: такая ситуация
требует сверки серверного результата оператором. Checkpoint содержит приватный
игровой контекст; храните его как закрытые данные, не как публичный лог.

## Экономия и измерения

Host использует `delta:true + stateDelta:true`. После первого полного снимка он
сохраняет один `stateDelta.revision` и отправляет его как
`knownStateRevision`. Сервер возвращает только изменившиеся сущности
(`upsert/remove/order`) и scalar `set/unset`; весь `sheets`, `facts`, NPC и
прочий неизменившийся state повторно не едет. SHA-256 учитывает кампанию,
timeline, narrator principal и projection. После применения patch host проверяет
checksum. Если сервер перезапустился или вытеснил baseline из bounded cache,
следующий read сам становится полным `resyncRequired:true`.

Старый `knownSections` остаётся только для совместимости с legacy-клиентами.
Исправленные старые сообщения не теряются: они возвращаются как изменившиеся
entities, а не отбрасываются ради экономии.

MCP narrator по умолчанию возвращает один компактный JSON в `content[].text`.
Тот же объект больше не дублируется в `structuredContent`; совместимость с
клиентом, которому он действительно нужен, включается отдельно через
`ODM_MCP_STRUCTURED_RESULTS=1`. Флаги `compact`, `policyMode`,
`includePolicyText` обрабатываются сайдкаром и не передаются в строгие схемы
Control API. Сокращённую доставку текста политики следует выбирать только после
установки полной политики в доверенный host.

Во время ожидания новых событий и физических костей модель не вызывается.
Состояние, каталог и технические результаты не пересылаются автору прозы.
Запросы ограничены по байтам без обрезания фактов. По умолчанию разрешены
24 шага арбитра на заявку и 240 генераций в час; оператор может явно задать
`ODM_NARRATOR_MAX_STEPS` и `ODM_NARRATOR_MAX_CALLS_PER_HOUR`.
Счётчики сохраняются, rewind не обнуляет расход.

OpenCode `session.generate` не возвращает usage. `/status` показывает число
вызовов и байты, а для токенов/стоимости этой части оставляет `null`, не нули.
Отдельный существующий cost tracker относится к ответам с реальным usage.
Серверные utility-вызовы доппельгангера не входят в счётчики этого host.
Размер JSON не равен числу токенов; итоговую цену и литературное качество надо
сравнивать на реальных игровых записях после отдельного smoke-теста.

## Границы

Автоматический host поддерживает spatial-кампании: входящие room-сообщения,
visibility/grants и `location_narrate` остаются scoped к комнате; audience
projection выполняется до state-diff. Обычная публичная narration при spatial
маршрутизируется через room-aware facade, а не публикуется глобально.

Только один host должен вести кампанию: распределённой lease пока нет. CAS,
commandId и receipt recovery защищают от повторного эффекта, но два независимо
запущенных ведущих всё ещё могут конкурировать за последующие ходы.

Ролевые инструкции уменьшают риск неправильного решения, но не доказывают полное
соблюдение RAW или отсутствие смысловой утечки в черновике самого ведущего.
Движок поддерживает не все правила; неоднозначные случаи остаются решениями DM.
Локальные проверки используют заглушки моделей и реальные форматы протокола,
не подтверждают художественное качество выбранной модели или боевое подключение.
