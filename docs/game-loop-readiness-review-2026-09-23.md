# Готовность игрового цикла через MCP — ревью 2026-09-23

Целевая модель: **игроки ходят через браузер, MCP — только доверенный пульт
оператора и внешнего ГМа**. Персональный MCP игроков не требуется. Код базового
цикла существенно усилен, но production-ready автономная игра пока не
подтверждена: на боевом сервере narrator-host не запущен.

## Проверенный путь

| Звено | Состояние после изменений | Граница |
| --- | --- | --- |
| Создать стол, участников, листы, технического DM | Операторские MCP tools; добавлен `campaigns.assign_dm_seat` | Создание/выдача персональных учётных данных остаётся отдельной auth-операцией |
| Принять действия людей | Браузер/REST `/actions` с личной сессией; общий ход и spotlight проверяются сервером | Это намеренная граница: операторский MCP не имперсонирует игрока |
| Автоматически услышать стол | `narrator/run.mjs` опрашивает durable story/Ask, хранит cursor, очередь, UUID команд и checkpoint | На production нет работающего host, модели и supervisor для недокерного запуска |
| Разрешить действия | `odm_narrator.read/catalog/invoke`, серверные кости, pending roll, encounter/initiative | Никакого текстового «успеха» до результата движка; host не заменяет движок |
| Выбрать темп/очерёдность | Лидерский UI и MCP `set_floor`, `request_response`; глобальный barrier или пакет `spotlight_ready` | В бою и при pending roll принудительный ответ/смена пола запрещены |
| Отыграть автопилот | Изолированный actor, `autopilot_action`, повторная проверка согласия, mute/skip/floor | Только явный self opt-in; боевую инициативу автопилот не имперсонирует |
| Исправить историю | MCP `edit_message`/`delete_message` с CAS, receipt и пересборкой очереди/памяти | Не откатывает HP/кости/инвентарь; для механики нужна отдельная команда или rollback |

## Существенные находки

1. **P0 — production не ведёт игру автоматически.** Read-only `odmctl status`
   и `odm-mcpctl status` показали здоровые приложение/MCP на коммите `ce39208`,
   но контейнера narrator нет, health host недоступен и checkpoint отсутствует.
   Изменения в этом рабочем дереве не развёрнуты. `watch-player.sh` — только
   ускоритель пробуждения, не источник истины. Для запуска нужны отдельный
   campaign-scoped narrator token, явный обработанный player cursor, выбранные
   provider/model, доступный HTTPS OpenCode и supervisor/container. Не выбирать
   cursor по текущему административному `currentSeq`.
   Повторная read-only проверка 2026-09-23 подтвердила тот же релиз и отсутствие
   narrator-контейнера; в `/opt/odm/config/app.env` обнаружены имена
   `ODM_MCP_NARRATOR_TOKEN`/`ODM_MCP_NARRATOR_CAMPAIGN_ID`, но нет имён
   `ODM_OPENCODE_*` или `ODM_NARRATOR_ADAPTER_MODULE`. Значения секретов не читались.
2. **P1 — production E2E не подтверждён.** `tsc --noEmit`,
   `next build --webpack` вне sandbox и локальная сборка Docker-образа host
   прошли; адаптер импортируется внутри образа без сети. В sandbox Next
   по-прежнему не может прочитать вывод дочернего `tsc --showConfig`, а
   Turbopack не проходит по симлинку `node_modules` за пределы дерева.
   Перед rollout нужна проверка полной сессии с моделью и тестовой кампанией,
   включая рестарт host и сохранённый cursor.
3. **P1 — коррекция текста не является revision history.** Актуальные
   сообщение/память/очередь синхронизируются, ID и seq события сохраняются,
   но старый текст после `edit_message` не хранится как отдельная
   административная версия. Для юридически значимого аудита нужна отдельная
   защищённая история правок; удалённые сообщения не должны всплывать в
   обычном narrator read. Dice и moderation reports остаются отдельно.
4. **P1 — лидер выше DM по управлению сюжетом, не по правилам.** Лидер может
   назначить DM seat, задать приватную one-turn директиву, выбрать spotlight,
   запустить ответ или досрочно запечатать глобальный раунд. Директива и
   событие ответа имеют приоритет в host. Но engine, initiative, приватность
   других игроков и безопасность не отменяются. Между конкурентными
   назначениями floor лидером и DM действует последний подтверждённый write;
   жёсткого отдельного «замка лидера» нет.
5. **P1 — восстановление production не доказано свежей проверкой.** В
   read-only статусе `odmctl` offsite backup не был настроен, а последняя
   restore-проверка датирована 2026-09-16. Перед обновлением приложения и
   запуском долгоживущего host нужен актуальный проверенный backup/restore.

## Что именно изменено

- Открыты и проверены MCP `edit_message`, `delete_message`, `set_floor`,
  `request_response`, `finish_global_round`, `autopilot_action` и назначение
  технического DM seat. Последовательные записи требуют актуальный seq;
  `commandId`/epoch и receipt защищают от двойной записи при timeout.
- Включение общего хода через MCP теперь ставит тот же серверный барьер, что
  и браузерная настройка, и публикует обновление для клиентов. Ручное
  управление небойным floor не может сломать активный глобальный раунд.
- Host обрабатывает `lead_response_requested` раньше более поздних реплик,
  передаёт приватную директиву только referee, пересобирает текущую пачку при
  редактировании и чистит compacted memory после удаления.
- Лидерский UI получил немедленный ответ и видимый roster автопилотов.
  Последовательный spotlight блокирует повторный ход уже ответившего игрока.
  После ответов всех выбранных игроков host разрешает одну пачку, а не
  отдельные реплики; раннее освобождение пола передаёт частичную пачку.
  Автопилот может отыграть согласившегося игрока и вне общего хода.
- Для Docker host используется существующий `narrator/Dockerfile`; монтируется только
  `state/narrator`, не весь `state` с SQLite. Старый checkpoint требует явного
  переноса; старт без адаптера, scoped token, доступного HTTPS OpenCode или
  образа отказывает до удаления предыдущего контейнера.

## Проверки и release gate

Пройдены: `tsc --noEmit`, `next build --webpack`, сборка Docker-образа host
и импорт адаптера в нём, интеграция narrator MCP, контракт инструментов,
права scoped token, лидерское закрытие общего хода, 41 тест orchestration,
5 тестов серверного хода, тест границы DM seat, 24 теста кубиков,
4 Python-теста контроллера и
6 тестов host (последние — с разрешённым loopback). Live E2E с моделью и
тестовой кампанией не проводился; реальные кампании не менялись.

Для реального запуска: (1) воспроизвести сборку приложения и host в окружении
релиза; (2) настроить отдельный narrator token/HTTPS модель и явно выбрать
player cursor; (3)
запустить host на тестовой кампании и проверить цикл Do → authoritative roll →
Narrate → release, Ask, оба режима хода, edit/delete и restart; (4) только
после этого обновлять production. Личный MCP gateway игроков не входит в
целевую модель. До выполнения этих условий статус — **автономный ГМ через MCP
не готов к production**.
