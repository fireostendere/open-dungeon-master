# Проверка развёртывания

Быстрые тесты эксплуатации не требуют модели, аккаунтов, GPU или сетевых запросов:

```bash
python3 -m unittest discover -s tests/deploy -v
bash install-server.sh --plan
```

На Windows CI дополнительно разбирает PowerShell AST установщика и запускает
`-Plan`, проверяя отсутствие изменений файловой системы.

Отдельный Linux job запускает **standalone installer** на точном
коммите: устанавливает зависимости, собирает Docker image этого форка, создаёт
шифрованную БД и администратора, запускает приложение. Затем проверяются реальные
restic backup/restore, возвращение HP/сюжета/сообщений/media, ошибочный новый
контейнер с откатом, журнал прерванного перехода и restart после `docker kill`.
Второй restic repository используется для теста копирования и off-site restore.

CI не выдаёт Docker-симуляцию из unit tests за интеграционную проверку: live job
использует настоящие Docker, драйвер шифрованной SQLite и restic.
Но он **не** подтверждает ваш DNS, ваш VPS, физическую перезагрузку Windows,
GPU-ускорение или качество конкретного LLM. В live job явно отключены внешние
скачивания Open5e/embedding assets и не выполняются платные model requests.
Проверяйте итог конкретного коммита: наличие workflow не означает, что он прошёл.

Существующие provider-тесты, production build, полный набор игровых тестов и
браузерный сценарий админки остаются отдельным workflow. Его успешность не является
полным аудитом всех сторонних зависимостей.

Артефакт `deployment-recovery-evidence` содержит машинный итог live-checks и
санитизированный health JSON. Ключи, admin.json и recovery kit в артефакт не входят.
